# Personal Academic Website — Anthropology Portfolio

A personal website for an anthropology professor: publications (English **and** Thai) with
abstracts and downloadable PDFs, fieldwork photo galleries, an about page and a contact page.

Built with **Astro + Tailwind CSS + Markdown** — a static site that is fast, easy to maintain,
and deployable to any static host (GitHub Pages, Netlify, Vercel, Cloudflare Pages, …).

> **Developers:** read **[DEVELOPER_GUIDE.md](./DEVELOPER_GUIDE.md)** first — it explains the
> architecture, how Markdown content flows into the pages, and how the English/Thai language
> system is wired and maintained.

---

## Tech stack

| Layer      | Choice                                       | Why                                                                  |
| ---------- | -------------------------------------------- | -------------------------------------------------------------------- |
| Framework  | [Astro](https://astro.build)                 | Content collections give typed, schema-validated Markdown; static output; zero JS by default |
| Styling    | [Tailwind CSS v4](https://tailwindcss.com)   | Utility-first design system with a custom academic theme             |
| Content    | Markdown (`src/content/`)                    | Abstracts, publication metadata and event descriptions live in `.md` files — easy to organise and edit |
| Extras     | `@astrojs/sitemap`                           | Automatic `sitemap-index.xml` on build                               |

No client-side framework is required — the only JavaScript is a few small progressive-enhancement
scripts (abstract "more…" toggles, a photo lightbox, and a list filter).

## SEO (built in)

- Unique `<title>` + meta description, canonical URLs, `robots.txt`, theme-color, author meta
- Open Graph + Twitter card tags with a generated 1200×630 share image (`public/og-image.png`)
- schema.org structured data: `Person` (home), `ItemList`/`ScholarlyArticle` (publication pages),
  `Event` (gallery pages), plus `WebSite` and `Organization` on every page
- `@astrojs/sitemap` → `sitemap-index.xml` on build

The share image is generated by `npm run generate:og` (a dependency-free PNG encoder) and is
regenerated automatically on `npm run build` via the `prebuild` script. If the owner's name
changes, update the `INITIALS` constant at the top of `scripts/generate-og-image.mjs` (and
`public/favicon.svg`).

## Languages (English / Thai)

The site is fully bilingual. **English** pages live at the root (`/about`, `/publications`, …) and
**Thai** pages under the `/th/` prefix (`/th/about`, `/th/publications`, …). A language switcher in
the navigation bar jumps between the same page in the other language; every page also carries
`hreflang` alternates and localized meta/Open Graph tags.

- UI strings live in `src/i18n/dictionaries.ts` — the `en` object defines the structure and the
  compiler guarantees `th` covers every key. Add new UI text there.
- Site identity (`src/site.config.ts`) is language-neutral, with a Thai `affiliationTh` line.
- Publication content is already language-specific (English vs Thai Markdown files), and the site
  UI around it switches: on `/th/…` you get Thai labels, badges, buttons and the Thai description
  of each event (`descriptionTh` in `src/content/events/*.md`).
- Routing follows Astro's i18n rule: with `prefixDefaultLocale: false`, the file structure must
  mirror the URL structure — English page files at `src/pages/` root, Thai page files under
  `src/pages/th/`. Both are thin wrappers around shared components in `src/components/pages/`.

## Project structure

```
public/
  publications_english/   ← PDFs served at /publications_english/*.pdf
  publications_thai/      ← PDFs served at /publications_thai/*.pdf
  pictures/
    album1/               ← photos for event "album1"
    album2/               ← photos for event "album2"
src/
  content/
    publications/
      en/*.md             ← one Markdown file per English publication
      th/*.md             ← one Markdown file per Thai publication
    events/
      *.md                ← one Markdown file per event/gallery
  content.config.ts       ← content schemas (validation rules)
  site.config.ts          ← site-wide settings: name, email, profiles, interests
  i18n/
    dictionaries.ts       ← EN/TH UI strings (single source of truth)
    index.ts              ← locale helpers (URL switching, neutral paths)
  components/
    pages/                ← shared page bodies rendered in both languages
  layouts/ components/ lib/ pages/ styles/
scripts/
  generate-placeholders.mjs  ← creates sample PDFs/images (safe to re-run)
```

## Adding a publication

1. **Drop the PDF** into `public/publications_english/` (English) or
   `public/publications_thai/` (Thai).
2. **Create a Markdown file** under `src/content/publications/en/` or `src/content/publications/th/`:

```markdown
---
title: "Ritual, Memory, and the Making of Sacred Landscapes in Northern Thailand"
authors:
  - "Niran Chanthana"
year: 2024
type: "Journal Article"          # Journal Article | Book | Book Chapter | Conference Paper | Review | Working Paper | Other
journal: "Journal of Southeast Asian Studies"
volume: "55"
issue: "2"
pages: "241–268"
language: "en"                   # "en" or "th"
pdf: "sacred-landscapes-north-thailand.pdf"   # file name inside the language folder
doi: "10.1017/xxx"               # optional
tags: ["religion", "ritual"]     # optional
---

Abstract goes here, in Markdown. Write as much as you like —
long abstracts automatically get a "more…" toggle on the website.
```

That's it — the publications page (`/publications/english` or `/publications/thai`) updates
automatically. Entries are sorted by year (newest first), and a search box filters the list.

> **Thai support:** `language: "th"` renders the page with `lang="th"` and Thai-capable fonts,
> and resolves the PDF against `public/publications_thai/`. Thai titles, abstracts and tags all
> work natively.

## Adding an event / photo gallery

1. **Create an album folder** under `public/pictures/`, e.g. `public/pictures/album3/`, and drop
   photos in it (`jpg`, `png`, `webp`, `gif`, `avif`, `svg` are supported).
2. **Create a Markdown file** under `src/content/events/`:

```markdown
---
title: "Fieldwork in Mae Hong Son"
date: 2025-03-10
location: "Mae Hong Son, Thailand"
album: "album3"            # must match the folder name in public/pictures/
cover: "photo-01.jpg"      # optional; defaults to the first photo
tags: ["fieldwork", "upland communities"]
---

Optional description of the event, in Markdown.
```

Each event gets its own child page (`/events/album3`) with a responsive photo grid and a
lightbox viewer (keyboard accessible: arrows navigate, Esc closes).

## Personalising the site

All site-wide settings live in **`src/site.config.ts`** — name, title, affiliation, email,
office address, academic profile links and research interests. Edit that one file to update the
entire site. Also set the `site` URL in `astro.config.mjs` (used for the sitemap and canonical
links).

To use a real profile photo, replace the monogram placeholder card on `src/pages/index.astro`
with an `<img>` tag.

## Deployment

The build output is fully static:

```bash
npm run build   # → dist/
```

Upload `dist/` to any static host. For **GitHub Pages**, add to `astro.config.mjs`:

```js
export default defineConfig({
  site: 'https://<user>.github.io',
  base: '/<repo-name>/',
  ...
});
```

See the [Astro deployment guide](https://docs.astro.build/en/guides/deploy/) for Netlify,
Vercel, Cloudflare Pages and other platforms.

## Customising the design

The theme (colours, fonts, spacing) is defined with CSS variables in
`src/styles/global.css` (`@theme { … }`). Headings use Lora, body text uses Inter, and Thai text
falls back to Noto Sans/Serif Thai.

## Sample content

Recreate placeholder PDFs and images (safe to run any time — existing files are never
overwritten):

```bash
node scripts/generate-placeholders.mjs   # or: npm run generate:placeholders
node scripts/generate-og-image.mjs       # or: npm run generate:og (also runs before every build)
```

Placeholder files generated by the first script are git-ignored; the OG share image and touch
icon (`public/og-image.png`, `public/favicon-180.png`) are real site assets and should be kept
in version control.
